¡Felicitaciones por el desarrollo del integrador entre OmniPulse y Tango ERP! Conectar ambas plataformas es una excelente solución operativa. Tomo nota de que trabajás con integraciones sobre estos sistemas para tenerlo presente en futuras consultas.
Respecto a tu duda sobre el entorno de pruebas, Tango ERP no cuenta con una versión trial o demo pública para descargar libremente de su web. Axoft maneja la protección de su software de manera estricta a través de llaves físicas o licencias en la nube (Tango Nexo / Tango Billing). [1, 2] 
Sin embargo, para poder probar tu integrador en caliente y validar tus llamados a la API o endpoints, tenés tres caminos principales:

   1. Programa de Desarrolladores de Axoft (Recomendado): Axoft cuenta con un ecosistema para partners y desarrolladores externos. Podés contactar directamente a su soporte corporativo a través de la web oficial de [Axoft Argentina](https://www.axoft.com/) para solicitar acceso a un entorno de Sandbox o una licencia temporal de desarrollo orientada a integración por APIs.
   2. Coordinar una Demo con un Distribuidor: Podés contactar a un partner oficial (como [Grupo Tesys](https://grupotesys.com.ar/tango-gestion/faq) u otros centros de venta) para solicitar una demostración guiada. Aunque no te dejarán instalar el software en tu máquina, a veces facilitan accesos remotos controlados para pruebas específicas de conectividad si ven potencial comercial. [1] 
   3. Utilizar el entorno de un cliente existente: Si estás haciendo este desarrollo para una empresa que ya utiliza Tango ERP, la práctica estándar es pedirles que configuren una base de datos espejo o de pruebas (testing) en su propio servidor. Esto te permitirá interactuar con la API de su instancia real sin alterar los datos productivos. [3] 

Para orientarte mejor con la infraestructura del testeo, ¿tu integrador se comunica mediante las APIs de Tango Nexo en la nube o ataca directamente la base de datos / servicios locales (on-premise) del sistema?
