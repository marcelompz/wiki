### 3.1 Hallazgo de seguridad en QA

El test `facturasend-api.spec.ts:37` esperaba `401` para `POST /api/v1/integrations/orderflow/webhook` sin credenciales, pero obtuvo `201`.

**Causa raíz:** `ApiKeyGuard` resuelve el tenant por host/subdominio. Al apuntar a `provecchio.com`, la request entra con contexto de tenant aunque no envíe JWT ni API key, por lo que el endpoint responde como autenticada implícitamente.

**Riesgo:** exposición no intencional del endpoint de webhook a llamantes sin credenciales desde el dominio público.

### 3.2 Fix aplicado

1. Agregado control de credenciales explícitas en `OrderFlowIntegrationController.receiveWebhook`:
   - Rechaza requests sin `Authorization: Bearer ...` ni `x-api-key`.
   - Preserva la resolución por host para requests autenticadas.
2. Agregado permiso RBAC `integrations:webhook:receive` al seed de permisos.
3. Aplicado `PermissionsGuard` + `@RequirePermissions('integrations:webhook:receive')` al endpoint.
4. Documentado en `docs/troubleshooting/162-integration-webhook-implicit-tenant-resolution-bypass.md`.
